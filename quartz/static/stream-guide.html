カプコン ファイティング コレクション（Steam版）のヴァンパイアセイヴァーで、対戦部屋を自動で立てて YouTube Live に無人で配信する仕組みを、自分の PC で作るための手順です。コードは配っていないので、自分で書くか AI に書かせる前提です。AI に渡す文面は AI に渡すプロンプト にあります。

1. できること

毎週決まった時刻に、人がいなくても次のことが順に起きます（時刻は例）。

毎日 12:00
次回の配信の予約枠を YouTube に作る（枠がもうあれば何もしない）
開始 10 分前
スピーカーをミュートする（ゲームの起動音で寝ている人を起こさないため。配信の音は出る）
開始 5 分前
ゲームを再起動し、決まったキー操作でパスワード付きのカスタムマッチのロビーを作り、自分は観戦に回る
開始
読み上げソフトとオーバーレイ（ゲーム画面に重ねるコメント欄や掲示板）のサーバーを起動 → OBS を起動して設定を検査 → 配信開始 → コメントを画面に出して読み上げる
終了
配信停止 → OBS を閉じる → ミュートを戻す → 説明欄に試合ごとのチャプターを書く → 対戦の記録を残す
終了 5 分後
ゲームを閉じる（ロビーも消える）

画面にはゲーム画面のほか、コメント欄、参加案内、ルールのメモ、下に流れる豆知識（Tips）と告知を重ねます。

3. 秘密情報の扱い

  • client_secrets.json・token.json・ストリームキー・obs-websocket のパスワードは、人に見せない・公開リポジトリに入れない。
  • AI に作業させるときも、これらのファイルの中身は読ませない・貼らない。存在と場所だけ伝える。
  • ロビーのパスワードそのものは、ログや画面に出さない。参加者向けに決め方を画面に出すなら、毎回変わる規則（日付から作るなど）にしておくと、荒らしに固定で覚えられにくい。

5. YouTube と Google Cloud の準備

前提：4 が済んでいる。
結果：ライブ配信が使え、ストリームキーが OBS に入り、client_secrets.json と token.json がフォルダにあって、--show が通る。

ここがいちばん手間のかかる所です。YouTube 側の準備と、プログラムが YouTube を操作するためのGoogle Cloud 側の準備の2つに分かれます。画面の名前は 2026 年 11 月時点のもので、Google 側の画面は名前や配置がよく変わります。見つからないときは画面上部の検索窓で探してください。

最終的にできるもの

もの何か扱い
ストリームキーOBS が YouTube へ映像を送るときの鍵秘密。OBS の配信設定に入れる
client_secrets.json「このプログラムは誰のものか」を Google に示すファイル秘密。プログラムのフォルダに置く
token.json初回にブラウザで許可すると作られる、無人で API を使うための鍵秘密。プログラムが自動で作る・更新する

5-1. YouTube 側

  1. ライブ配信を有効にする。YouTube Studio の右上「作成」→「ライブ配信を開始」。初めてなら電話番号の確認を求められ、使えるようになるまで最大 24 時間かかる。
  2. ストリームキーを決める。ライブ配信の画面の「ストリームキーを選択」で、再利用できるキー（最初からある「Default stream key」でよい）を選ぶ。キーを毎回作り直さず、ずっと同じキーを使う。
  3. OBS にキーを入れる。配信専用のプロファイルで「設定」→「配信」→ サービス「YouTube - RTMPS」→「ストリームキーを使用」を選び、キーを貼る。アカウント連携（「アカウント接続」）は使わない。連携にすると、OBS は配信のたびに「どの枠に流すか」を人が選ぶのを待って送り始めず、無人では止まってしまう。ストリームキー方式なら OBS は決まったキーに黙って送り、同じキーに結び付けた予約枠（自動開始オン）が受信を見て自動で始まる。代わりに OBS の中の YouTube チャット欄は出なくなるが、コメントはプログラムが別に取るので困らない。
  4. ゲームのタイトルを設定する。Studio の動画の詳細にある「ゲームのタイトル」（カテゴリを「ゲーム」にすると出る欄）は API で設定できない。予約枠ができたら、Studio で手で「Vampire Savior」などを選ぶ。一度設定すれば、プログラムが説明欄を書き換えても消えない。

5-2. Google Cloud のプロジェクトを作る

  1. Google Cloud コンソールを開き、配信するチャンネルを持っている Google アカウントでログインする。
  2. 画面上部のプロジェクト選択 →「新しいプロジェクト」→ 名前（例：vs-stream）を付けて「作成」。請求先アカウント（クレジットカード）は要らない。
  3. 作ったプロジェクトが上部で選ばれていることを確かめる。以降はすべてこのプロジェクトの中で作業する。
  4. 左のメニュー「API とサービス」→「ライブラリ」→「YouTube Data API v3」を検索して開き、「有効にする」。

5-3. 同意画面（Google Auth Platform）を作る

「どんなアプリが、何の権限を求めるか」を Google に登録する画面です。自分しか使わないアプリでも必要です。

  1. 「API とサービス」→「OAuth 同意画面」を開くと「Google Auth Platform」に移る。「開始」を押す。
  2. アプリ情報：アプリ名（自分しか見ないので何でもよい。例：vs-stream）、ユーザー サポートメール（自分）。
  3. 対象：「外部」を選ぶ（個人の Gmail では「内部」は選べない）。
  4. 連絡先情報：自分のメールアドレス。
  5. ポリシーに同意して「作成」。
  6. 左の「データアクセス」→「スコープを追加または削除」で、次の2つに印を付けて保存する。
    https://www.googleapis.com/auth/youtube
    https://www.googleapis.com/auth/youtube.force-ssl
  7. 左の「対象」→「テストユーザー」に、配信するチャンネルの Google アカウントを追加する。

5-4. OAuth クライアントを作って JSON を取る

  1. 左の「クライアント」→「クライアントを作成」。
  2. アプリケーションの種類は「デスクトップ アプリ」。名前は何でもよい。「作成」。
  3. 作成直後の画面で JSON をダウンロードする。後からはシークレットを表示できないことがあるので、この時点で必ず保存する。
  4. ダウンロードしたファイルの名前を client_secrets.json に変え、プログラムのフォルダに置く。
「ウェブ アプリケーション」を選ぶと、初回の許可で redirect_uri_mismatch になります。種類を間違えたらクライアントを作り直してください。

5-5. 「本番環境」に切り替える（7日問題）

ここを飛ばすと、毎週の自動実行が 7 日後に必ず止まります。公開ステータスが「テスト」のままだと、token.json の中の更新用トークンが 7 日で失効し、invalid_grant というエラーになります。
  1. 「対象」の「公開ステータス」で「アプリを公開」→ 確認。ステータスが「本番環境」になる。
  2. Google の審査（確認）は申請しなくてよい。未確認のアプリとして自分のアカウントだけで使う。
  3. 本番環境にした後は、使わない期間が 6 か月続かない限りトークンは切れない。

5-6. 初回の許可（token.json を作る）

  1. プログラムを「認可」の動きで実行する（例：schedule.py --auth のような入口を作っておく）。ブラウザが開く。
  2. 配信するチャンネルの Google アカウントを選ぶ。チャンネルが複数ある場合は、ここで配信するチャンネルを選ぶ。
  3. 「Google はこのアプリを確認していません」と出たら、「詳細」→「（アプリ名）（安全ではないページ）に移動」。自分で作ったアプリなので問題ない。
    ここが一番迷いやすい。画面で目立つ大きなボタンは「安全なページに戻る」で、これを押すと許可せずに終わってしまう。進むための選択肢は、左下の小さな文字のリンク「詳細」（「Advanced」）で、押すと下に出てくる、さらに小さなリンク「（アプリ名）（安全ではないページ）に移動」をクリックする。ボタンではなくただの文字に見えるので見落としやすい。
  4. YouTube の管理の権限を「許可」する。ブラウザに完了の表示が出て、フォルダに token.json ができる。
  5. 予約枠の一覧を見るだけの動き（例：--show）を実行して、API が通ることを確かめる。
  6. 8 日以上たってからもう一度 --show を実行し、まだ通ることを確かめる。通れば 7 日問題は解決している。

6. 読み上げと音の準備

前提：4 が済んでいる。
結果：テストの読み上げが CABLE Input に鳴り、OBS の「CABLE Output」の音量メーターが動く。スピーカーからは聞こえない。

  1. VB-Audio Virtual Cable を入れる（ドライバーの導入の許可は人）。再生デバイスに「CABLE Input」、録音デバイスに「CABLE Output」が増える。
  2. VOICEVOX を入れ、話者を決める（話者 ID で指定する）。プログラムからエンジンが起動していなければ起動する。声を聞き比べて話者を選ぶところだけ人。
  3. 読み上げの wav は「CABLE Input」へ鳴らす。OBS には「CABLE Output」を音声入力として足す。これで読み上げはスピーカーから出ずに配信にだけ乗る。
  4. ゲーム音は OBS のゲームキャプチャで直接拾う（アプリの音声キャプチャを別に足すと二重になる）。
スピーカーのデバイスをミュートしても、OBS はアプリから直接音を拾うので配信の音は消えません。アプリ個別のミュートは配信からも消えるので使いません。

読み上げの小技

  • 長いコメントは 60 字ほどで切る。読み上げ待ちが溜まったら古いものから捨てる。
  • 英字のすぐ後に記号やかなが続くと VOICEVOX が読みを崩す（gg! が「グ」になる）。読み上げる文だけ、英字の後に空白を挟む。
  • 「!」が入ったコメントや「うおおお」だけ反響を掛ける、のように、コメントの中身で OBS のフィルターをオン・オフすると楽しい。反響を切るときは前の声の残響が消えるまで 2 秒ほど待つ。
  • NG 語の一覧を用意し、当たったコメントは表示も読み上げもしない。一覧は一から作らず、web で公開されている日本語の不適切語のデータセットから適当なものを採用し、自分の配信に合わせて足し引きする（利用条件は採用する前に確かめる）。データセット探しと取り込みは AI セッションに頼める。

7. OBS の準備

前提：4〜6 が済んでいる。
結果：配信専用のプロファイルとシーンがあり、AI セッションから WebSocket に接続でき、ブラウザソースにオーバーレイが映る。

AI は WebSocket 経由で OBS を操作するので、先に 4 番目の WebSocket サーバーを人が有効にしておくと、残りの組み立ては AI に頼めます。

  1. 配信専用のプロファイルを作る。配信先とキーはここに入れる（キーを貼るのは人）。普段使いのプロファイル（Twitch など）とは分ける。
  2. 配信用のシーンを作り、ゲームキャプチャ、読み上げ（CABLE Output）、ブラウザソース（オーバーレイ）を入れる。ゲームキャプチャは人が OBS の画面で作り、ゲームの窓を選んで切り抜きを合わせる（AI はこのソースの位置や切り抜きを変えない）。
  3. ブラウザソースは 1920x1080 で、URL は自分の PC で動かす表示サーバー（例：http://127.0.0.1:8080/overlay.html）。
  4. 「ツール」→「WebSocket サーバー設定」で「WebSocket サーバーを有効にする」に印を付ける。プログラムはここから OBS を操作する（起動の確認、プロファイルの検査、配信の開始と停止、スクリーンショットなど）。
    同じ画面の「認証を有効にする」のパスワードは、OBS を外から操作するための合言葉。YouTube や Google のパスワードとは関係なく、OBS の中だけで使う。OBS が作った値をそのまま使えばよく、プログラムは OBS の設定ファイル（%APPDATA%\obs-studio\plugin_config\obs-websocket\config.json）から読めるので、どこかに書き写す必要もない。同じ PC やネットワークのほかのプログラムに勝手に配信を操作されないためのものなので、認証は切らない。
  5. （任意）ゲーム音や読み上げに VST2 リバーブのフィルターを付ける。オン・オフはプログラムから切り替えられる。掛かり具合はプラグインの画面で聞きながら人が調整する。
OBS は --profile に存在しない名前を渡すと、黙って既定のプロファイルで起動します。配信を始める前に、いまのプロファイル名を obs-websocket で確かめ、違えば配信しないようにしてください。配信先を間違える事故を防げます。

8. AI セッションで作る

前提：5〜7 が済んでいる（Google 側の準備と、WebSocket の有効化は人にしかできない）。
結果：下の部品がそろい、全部の --selfcheck が通る。

配信プログラムは AI セッションに作ってもらいます。AI に渡すプロンプトの「全体の依頼」を、【】を自分の値に書き換えてから渡し、AI が段階ごとに止まって報告するたびに中身を確かめて次へ進めます。作る部品は次のとおりです。

部品すること
設定の読み込み人が触るのは設定ファイル1つだけにする。読み込み時に必須の項目と型を確かめる
予約枠の作成次回の枠がなければ作る。タイトル・説明・タグ・サムネ（フォルダからランダム）・言語を入れる
OBS の操作起動、プロファイルとシーンの検査、配信開始と出力が本当に動いたかの確認、終了
コメントの取得pytchat で取り、NG 判定、YouTube のお知らせ（システムメッセージ）の除外
読み上げVOICEVOX で合成し、仮想ケーブルへ順番に鳴らす
オーバーレイローカルの HTTP（HTML を配る）と WebSocket（コメントを送る）のサーバー。HTML 側でコメント欄、メモ、Tips と告知の流れる掲示板を描く
チャプターと記録配信中に OBS のスクリーンショットから試合の頭・キャラ・勝敗を読み、終了後に説明欄へチャプターを書き、CSV に残す（13）
タスク登録設定ファイルの開始・終了時刻から、タスク スケジューラのタスクを登録し直す

どの部品にも --selfcheck のような「外につながずに中身だけ確かめる」入口を付けておくと、設定を変えたときに安心です。

9. ロビーを自動で立てる

前提：8 の AI セッションを始めている。キー列を実機で確かめてある。
結果：--dry で手順が表示され、実行するとロビーが建って観戦に切り替わる。

ゲームの画面は読み取らず、毎回ゲームを起動し直して、決まったキー列を送るだけにすると安定します。ロビーの設定は起動するたびに初期値に戻るので、いつも同じ手順で済みます。

  1. ゲームが動いていれば終了させ、Steam から起動する。
  2. タイトル → オンラインプレイ → カスタムマッチ → ロビー作成、と進むキー列を、自分の環境で一度手で確かめて記録する。
  3. ロビー作成画面で変えたい項目（参加人数、パスワードなど）だけ操作する。パスワードは数字キーで直接打てる。
  4. ロビーが建ったら少し待ってから、観戦に切り替えるキー（左 Ctrl）を送る。
  5. 最後にスクリーンショットを1枚残す。毎回同じファイルに上書きするログで、普段は見ない。ロビーが建っていなかったときに、どこで止まったかを調べるために使う。
キー入力は Python の ctypes から Windows の SendInput を、スキャンコード方式で送ると届きます。SendKeys のようなウィンドウメッセージ方式は届きません。仮想パッドや AutoHotkey は要りません。

10. 設定ファイルの考え方

前提：8 の段階 1（設定の雛形）ができている。
結果：自分の値（時刻、文言、デバイス名）が入り、--selfcheck が通る。

TOML 1枚にまとめ、表ごとに分けます。

[screen]     画面のタイトル、参加案内、ロビーのキー操作、ルールのメモ
[speech]     話者、速度、最大文字数、出力デバイス（CABLE Input）、反響の条件
[youtube]    開始・終了時刻、公開設定、カテゴリ、タグ、説明文、サムネの置き場所
[obs]        プロファイル名、シーン名、ミュートするか、反響を使うか
[announce]   告知（日付付きの行はその日を過ぎたら自動で流さない）
[tips]       画面下に流す豆知識（1行1件、# の行は読み飛ばす）
[ng]         読み上げも表示もしない語
  • 配信中に書き換えて機能するのはメモ・告知・Tips・NG 語だけにし、それ以外は次回から機能する、と決めておくと迷わない。
  • 書き換えたら selfcheck で TOML が壊れていないか確かめる。
  • パス・ポート・デバイス名など PC ごとに違うものは、全部この設定ファイルに寄せる。

結果：5 つのタスクが登録され、登録内容と設定の差の表示が空になる。

12. テストの順番

前提：11 が済んでいる。
結果：限定公開の 5 分の配信でコメントが画面に出て読み上げられ、終わった後に説明欄へチャプターが付く。本番の初回を見守り終える。

  1. selfcheck を全部通す。
  2. オフラインのコメントテスト：打った文を、本番と同じ NG 判定・読み上げ・オーバーレイに流す（YouTube にはつながない）。
  3. OBS をつないで画面の見た目を確かめる（ブラウザソースを読み直して、スクリーンショットを撮る）。
  4. 限定公開で 5 分の予約枠を作り、5 分だけ本当に配信する。非公開の枠ではコメントが取れないので、限定公開にする。
  5. ロビーの自動作成を単体で動かし、残したスクリーンショットで確かめる。
  6. 本番の時刻でタスクを動かす。最初の数回は近くで見守る。

13. チャプターの取り方

配信のアーカイブに、試合ごとのチャプターを自動で付ける仕組みです。部品の中でいちばん手間がかかります。画面を読む判定は AI に作ってもらえますが、比べる見本の画像は、実際のゲーム画面から用意する必要があります。

試合の頭を見つける

  • 試合の頭には、毎回「対戦を開始します」→ ロゴ → キャラ選択 → VS → READY の順に画面が出る。READY は各ラウンドの頭にも出るので使わず、残りの4つのどれかが写ったら試合の頭とみなす。
  • 配信中、OBS のゲーム画面のスクリーンショットを数秒おきに撮る。上下の黒帯を落として 1280x720 にそろえ、画面の決まった範囲を見本の画像と比べる。範囲は、毎回同じ絵になり、プレイヤー名やロビー ID が写らない所だけにする。
  • 比べるときは画像を縮小して、明るさの差の平均を見る。差がしきい値より小さければ一致とする。しきい値は、録画した配信で「一致する画面」と「一致しない画面」の差を測って決める。
  • 同じ試合を二重に数えないよう、一致する画面が 20 秒ほど途切れるまでは次を数えない。

キャラと勝敗を読む

  • キャラ名は、VS の画面などに出る名前の文字（黄〜橙の部分）を、キャラごとの見本と比べて読む。
  • 勝敗は、試合後の結果画面の見出し（RESULT CUSTOM MATCH）が出たときに読む。
  • 読めなかったところは「不明」と書く。チャプターの時刻さえ合っていれば、キャラが読めなくても役に立つ。

見本の画像を用意する

  • 配信のアーカイブ（録画）から、試合の頭の4つの画面、結果画面、各キャラの名前が出た画面のフレームを切り出す。切り出しと、見本の画像を作る道具は AI に作ってもらい、どの場面のフレームを使うかは人が選んで確かめる。
  • 作った見本で、録画を最初から最後まで走査して、試合の頭を取りこぼしていないか、余計に数えていないかを確かめる。

説明欄に書く

  • 時刻は、YouTube の開始時刻ではなく OBS が送り始めた時刻を基準にし、試合の頭の 2 秒手前を指す。
  • 1行は「時刻 [試合番号] 左キャラ,勝敗,右キャラ」の形にする（例：55:51 [1] GA🐺,o-x,🐺GA）。行頭の絵文字は YouTube に消されるので、左キャラの絵文字は名前の後ろに付ける。試合番号は CSV の記録と同じにする。
  • YouTube のチャプターの決まり（14）に合わせる。101 行以上になる場合は、溢れた試合を 100 行目にまとめる。
  • 書いた後に視聴ページを見て、チャプターが出ていなければ一度外して付け直す。

16. ハマりどころ

症状対処
OBS が配信開始の直後に落ちる起動してから 30 秒ほど待ってから配信を始める
OBS の起動時にセーフモードの確認が出て、無人の起動が止まる前回 OBS が落ちると、次の起動でこの確認が出る。起動する前に %APPDATA%\obs-studio\.sentinel の中の run_* を消すと出ない
配信開始が成功と返るのに出力が動いていない開始後に出力が動いているかを数秒おきに確かめ、20 秒ほど待つ
シーンの変更が消えるOBS は終了時にしか保存しない。変更したら保存の操作も送る
読み上げだけが消えるセキュリティソフトがマイク扱いの音声入力（CABLE Output）を止めることがある。許可の設定を確かめる
オーバーレイの画像が途中までしか表示されないセキュリティソフトが、自分の PC の中の HTTP の通信を一定の大きさ（この環境では 64KB）で止めることがある。表示サーバーが配るファイル（画像など）は、1 ファイル 64KB 未満に収める。大きい画像は縮小するか、軽い形式（JPEG など）で保存し直す
掲示板の Tips・告知の読み込みがたまに失敗するオーバーレイは書き換えを拾うため、告知は 1 件流すたびに、Tips は一巡するたびに、設定ファイルの中身を表示サーバー経由で読み直す。この読み込みが、PC の中の通信でも数 % 失敗することがある（150 回中 4 回の例）。失敗したときは前に読めた内容で流し続ける作りにする。コメントは別の経路（WebSocket）で届くので関係ない
コメントが取れないpytchat は接続した後のコメントしか取れない。非公開の配信では取れない
チャプターがプレーヤーに出ない101 行以上だと出ない（100 行まで）。書いた直後に出ないこともあるので、少し待って視聴ページを確かめ、出ていなければ付け直す
チャプターの時刻がずれるYouTube の開始時刻は OBS が送り始めた時刻より数秒遅い。OBS の送信開始を基準にする
ロビーのキーを取りこぼす画面の切り替わりの後は数秒待ってから次のキーを送る
